# 출퇴근 스크롤 시간 선택 설계

## 목표

직원이 출퇴근 등록 시 현재 시각과 가까운 30분 단위 시간을 기본값으로 확인하고, 당일의 시·분을 스크롤하여 실제 등록할 시간을 선택한다.

## 사용자 흐름

1. 직원이 출근 또는 퇴근 버튼을 누른다.
2. 시간과 분을 각각 선택하는 스크롤 모달이 열린다.
3. 시간은 00~23시, 분은 00분 또는 30분만 표시한다.
4. 현재 시각에 가장 가까운 30분 단위 시간이 기본 선택된다.
5. 직원이 시간을 확인하거나 변경한 뒤 등록 버튼을 누른다.
6. 선택 시간이 Google Sheets에 저장되고 기존 완료 메시지와 화면 갱신이 실행된다.

## 선택 규칙

- 선택 날짜는 당일로 고정한다.
- 당일 과거 시간은 선택할 수 있다.
- 미래 시간은 버튼을 누른 현재 시각으로부터 최대 30분 후까지만 허용한다.
- 허용 범위를 초과한 조합은 선택할 수 없도록 비활성화하거나, 등록 시 이해하기 쉬운 안내를 표시한다.
- 23시대에는 다음 날짜로 넘어가는 시간은 허용하지 않는다. 가장 늦은 선택값은 23:30이다.
- 기본값은 현재 시각에 가장 가까운 유효한 30분 단위 값이다.
  - 08:12 -> 08:00
  - 08:20 -> 08:30
  - 08:48 -> 09:00
  - 23:50 -> 23:30

## 구현 범위

- `apps-script/Index.html`
  - 기존 3개 라디오 시간 선택 UI를 시·분 스크롤 선택 UI로 교체한다.
  - 기본 시간 계산, 선택 가능 범위 검증, 접근성 상태를 추가한다.
  - 기존 `submitAttendance()` 호출과 로딩·중복 클릭 방지는 유지한다.
- `release/scripts/qa-static.mjs`
  - 가장 가까운 30분 기본값, 미래 30분 제한, 자정 경계를 정적으로 검증한다.

## 유지 사항

- `Code.gs`의 저장 API와 Google Sheets 데이터 구조는 변경하지 않는다.
- 선택된 `HH:mm` 값은 기존 API를 통해 그대로 저장한다.
- 로그인, 자동 로그인, 출퇴근 중복 방지, 근태 로그, 관리자, 월별 조회 및 계산식은 변경하지 않는다.
- GPS 제거 상태와 24시간 등록 가능 정책을 유지한다.

## 오류 처리

- 선택값이 없거나 유효하지 않으면 모달을 유지하고 안내 메시지를 표시한다.
- 미래 30분 제한을 초과하면 `현재 시각에서 30분 후까지만 선택할 수 있습니다.`를 표시한다.
- 서버 저장 실패 시 기존 오류 Snackbar를 사용하고 버튼을 다시 활성화한다.

## 완료 기준

- 출근·퇴근 모두 동일한 스크롤 선택기를 사용한다.
- 분은 00분과 30분만 선택할 수 있다.
- 기본값과 미래 30분 제한이 경계 시각에서도 일관되게 동작한다.
- 선택한 시간이 서버로 전달되고 기존 시트 저장·중복 방지 기능이 유지된다.
