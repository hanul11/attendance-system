# 관리자 근태 수정 요청 처리 설계

## 목표

직원이 제출한 근태 수정 요청을 관리자가 LOGIFLOW 관리자 화면에서 확인하고, 요청값을 조정한 뒤 승인하거나 고정 사유로 반려할 수 있게 한다. 기존 Google Sheets 구조와 근태 계산 방식을 유지하고 관리자 확인 업무를 앱 안에서 끝내는 것이 목표다.

## 범위

- 관리자 화면의 대기 요청 목록과 건수 표시 유지
- 요청 상세 다이얼로그 추가
- 출근·퇴근 요청값을 30분 단위로 조정
- 연차 요청값을 전일 또는 반일로 조정
- 승인 및 반려 처리
- 처리일시, 처리자, 처리 결과 기록
- 처리 완료 요청을 대기 목록에서 자동 제거

다음 항목은 이번 범위에서 제외한다.

- 새로운 Google Sheets 시트 또는 컬럼 생성
- 직원·근태현황·근태로그 시트 구조 변경
- 조출, 잔업, OT, 휴게시간 계산 방식 변경
- 푸시 알림 추가
- 일반 직원의 직접 근태 수정

## 사용자 흐름

1. 관리자는 관리자 화면의 `근태 수정 요청` 목록에서 요청을 선택한다.
2. 상단에 배치된 요청 상세 다이얼로그에서 직원, 대상 날짜, 요청 사유, 기존값, 요청값을 확인한다.
3. 관리자는 최종 반영값을 조정할 수 있다.
   - 출근·퇴근: 00:00부터 23:30까지 30분 단위
   - 연차: 전일 또는 반일
4. 승인하면 확인 다이얼로그를 거쳐 근태현황에 최종값을 반영한다.
5. 반려하면 다음 고정 사유 중 하나를 선택한다.
   - 기존 기록과 일치함
   - 요청 시간을 확인할 수 없음
   - 요청 사유가 충분하지 않음
   - 증빙 또는 추가 확인 필요
6. 처리 후 대기 목록과 관리자 요약을 다시 불러오며 완료 메시지를 Snackbar로 표시한다.

## 서버 구조

`AttendanceRequests.gs`에 관리자 전용 처리 API를 추가한다.

### 입력

- 관리자 사번
- 요청 로그 행 번호
- 처리 유형: 승인 또는 반려
- 최종 반영값
- 반려 사유 코드

서버는 클라이언트가 전달한 직원 정보나 날짜를 신뢰하지 않고 요청 로그 행을 다시 읽어 처리 대상을 확인한다.

### 권한과 유효성 검증

- 관리자 사번은 `CONFIG.adminEmployeeId`와 일치해야 한다.
- 요청 로그 행은 실제 `근태 수정 요청` 형식이어야 한다.
- 이미 처리된 요청은 다시 처리할 수 없다.
- 출근·퇴근 최종값은 30분 단위여야 한다.
- 연차 최종값은 `1` 또는 `0.5`만 허용한다.
- 반려 시 허용된 고정 사유 중 하나가 필수다.

## 승인 처리

승인 시 직원 사번과 이름을 직원 명단에서 다시 확인하고, 근태현황에서 해당 직원 블록과 대상 날짜 행을 찾는다.

- 출근: 해당 날짜의 출근 셀에 최종값 기록
- 퇴근: 해당 날짜의 퇴근 셀에 최종값 기록
- 연차: 해당 날짜의 사용연차 셀에 최종값 기록

기존 계산 열의 수식과 시트 서식은 변경하지 않는다. 기록 후 `SpreadsheetApp.flush()`를 호출하여 계산 결과가 반영되도록 한다.

## 반려 처리

반려 시 근태현황은 변경하지 않는다. 선택한 반려 사유와 처리 상태만 근태로그 요청 행에 기록한다.

## 근태로그 처리 규칙

새 시트와 새 컬럼을 만들지 않는다.

- 요청 당시 기존값과 요청값은 유지한다.
- 요청 유형에는 처리 결과를 식별할 수 있는 승인 또는 반려 상태를 반영한다.
- 수정시간에는 관리자 처리 시간을 기록한다.
- 수정자에는 관리자 사번을 기록한다.
- 관리자가 승인값을 조정한 경우 최종 반영값을 처리 결과에 포함해 추적 가능하게 한다.

대기 요청 조회는 처리시간 또는 처리 결과가 있는 행을 제외한다. 따라서 승인값이 직원의 최초 요청값과 달라도 대기 목록에 남지 않는다.

## 관리자 UI

기존 LOGIFLOW Design System을 사용한다.

- 기존 요청 행은 버튼 형태를 유지한다.
- 요청 선택 시 별도의 상세 다이얼로그를 연다.
- 다이얼로그는 화면 상단 25~30% 위치에 표시하고 배경 스크롤을 잠근다.
- 기존값과 요청값은 비교하기 쉽게 같은 행에 배치한다.
- 최종 반영값 선택 컨트롤을 제공한다.
- `승인`은 Primary 버튼, `반려`는 Secondary 또는 경고 버튼으로 구분한다.
- 반려를 선택하면 고정 사유 선택 영역을 표시한다.
- 저장 중 버튼 비활성화와 로딩 표시로 중복 처리를 막는다.

## 오류 처리

- 권한 오류: `관리자 계정에서만 처리할 수 있습니다.`
- 이미 처리됨: `이미 처리된 수정 요청입니다.`
- 대상 행 없음: `해당 날짜의 근태 기록을 찾을 수 없습니다.`
- 값 오류: 항목에 맞는 30분 단위 시간 또는 연차값 안내
- Sheets 오류: 공통 오류 다이얼로그 또는 Snackbar 사용

서버 오류가 발생하면 다이얼로그 입력값을 유지하여 관리자가 다시 시도할 수 있게 한다.

## 성능과 동시성

- 요청 처리 시 필요한 요청 로그 행과 해당 직원 근태 블록만 읽는다.
- `LockService`로 동시에 같은 요청을 처리하는 상황을 방지한다.
- 처리 성공 후 관리자 대시보드를 한 번만 다시 조회한다.
- 기존 관리자 자동 갱신 동작과 중복 API 호출이 발생하지 않도록 처리 중 플래그를 사용한다.

## 테스트 기준

- 일반 직원이 처리 API를 호출하면 거부된다.
- 승인한 출근·퇴근 시간이 근태현황의 정확한 날짜와 직원 셀에 반영된다.
- 승인한 연차값이 정확히 반영된다.
- 관리자가 요청값을 조정해 승인해도 요청이 대기 목록에서 제거된다.
- 반려하면 근태현황은 변경되지 않고 선택 사유와 처리자가 기록된다.
- 이미 처리된 요청의 중복 승인이 거부된다.
- 잘못된 시간과 반려 사유가 거부된다.
- 기존 로그인, 출퇴근 등록, 근태 조회, 관리자 조회 기능의 정적 QA가 모두 통과한다.
